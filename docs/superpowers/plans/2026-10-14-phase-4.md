# OHMI Phase 4 implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline; owner requests autonomous implementation, not approval pauses. Steps use checkbox tracking.

**Goal:** Gemini chat, private assignment analysis, saved contextual tutorials, and enforceable usage limits without changing the approved interface.

**Architecture:** Trusted worker messages call authenticated Supabase Edge Function; RLS owner data plus service-only transactional quota/persistence RPCs. Gemini REST/core validation has no extension secret.

**Tech stack:** Existing WXT/React/TypeScript/Vitest/Playwright/Supabase JS 2.117.3, CLI 2.120.0, Gemini 3.8 Flash REST, Deno Edge Functions.

**Spec:** [Design](../specs/2026-10-14-phase-4-design.md).

## Global constraints

Preserve existing unpacked build path/ID, PNG, phases 1–3, pending SMTP. Keep credentials server-only. Add new migrations. No Phase 5. Current checkout feature branch `codex/phase-4` preserves callback identity; cost is less filesystem isolation. Avoid new frontend dependencies.

## Review focus

- Cross-user IDs, deleted assignments, or stale tabs must never send another student's file/context to Gemini.
- Concurrent/replayed/failed requests must neither evade cost limits nor duplicate persisted turns.
- Prompt injection or malformed/truncated provider output must not become trusted instructions, tools, HTML, or saved invalid tutorials.
- Account switches/reloads must recover correct history/progress without retaining another owner's UI.
- Provider delays, blocked content, quota exhaustion, and save failures must produce recoverable truthful states without exposing secrets.
