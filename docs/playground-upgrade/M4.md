# M4: local presentation, accessibility and release review

M4 was explicitly approved for local presentation, mobile/accessibility and release-readiness work. No live AI request, hosted change, push or deployment was performed. The legacy Playground remains default. M3 checkpoint `f655e1f` is the local rollback point.

## Changes

The existing OHMI shell now places the editor ahead of file/project/help details. Core controls retain the approved Geist, semantic mint/light/charcoal palette and original mascot. Host state reflects actual native view and simulation state, including changes made inside the native UI. Zoom in/out/fit is available through labeled DOM buttons.

**Parts & inspector** opens the existing Radix dialog on desktop and a viewport-contained phone sheet. It exposes all 791 native catalog entries with their actual preset properties, search/empty states, placed-component inspection, property controls, complete Arduino sketch editing, coordinate placement, pin-to-pin wiring in all three views and removal. Changes use the existing native tools/history. No parts, solver, code interpreter or exporter were reimplemented. Unapplied inspector edits are guarded before closing/switching/refreshing; modal focus returns to its trigger. Fields use 16px type on phones and controls have at least 44px targets. The technical native canvas and original native menus remain available.

The reviewer flagged the crowded first phone viewport. The explicit **Focus canvas** layout now brings the whole editor into the useful area between the app header and bottom navigation, with a visible **Return to controls** action. It changes presentation/scroll only; the iframe key, engine and document stay intact. Returning restores keyboard focus. It does not hide or remove editor actions.

Reference inspection: the public [Wokwi Uno editor](https://wokwi.com/projects/new/arduino-uno) was visually inspected, including its parts picker. Adapted principles: compact run/add/zoom controls, a search-first catalog and on-demand editing space. No artwork, branding, source code or assets were copied. This is not a claim that Wokwi's mobile layout was audited. The user's saved design-reference-library and existing OHMI design remain authoritative.

## Verification

- 75 PWA unit tests and TypeScript pass. Protocol negatives cover invalid zoom/catalog options; current source/runtime hashes match the rebuilt manifest.
- PWA production build passes, with the existing unpdf `import.meta` warning unchanged.
- Actual WASM with synthetic Auth/PostgREST: all catalog presets, empty search, add/move/wire, full sketch/property application, unapplied-change protection, focus return, live simulation/view state, zoom and exact `.dez` pass.
- Desktop 1440×1100, tablet 820×1180 and phone 390×844 in light/dark where captured; emulated touch, reduced motion, 44px sheet targets, no document overflow, viewport-contained sheet and persisted theme pass. Scoped axe finds no violations in the tools dialog. Phone focus mode fits canvas above fixed navigation.
- M1 native/browser regression passes, including 117 native assertions, A/B timelines, invalid-sketch recovery, three views/five exports, undo/redo, sandbox, account teardown and loss guards. M2 private persistence/replacement/legacy regression and M3 mock planner/workspace/recovery regression pass.
- No database logic changed in M4. M3's real disposable PostgreSQL migration/reliability results remain applicable; M4 browser storage checks use the existing boundary double.

The first keyboard test pressed Enter while initial private-load state disabled the trigger; final tests use an enabled trigger and verify Escape/focus return. Native HTML form labels include explicit control names so select option text does not pollute accessible names. Phone dialog translation was corrected after viewport bounds exposed the default centered-dialog offset. These are tested fixes, not claims of physical-device certification.

Evidence: `evidence/m4-browser.json`, `m4-native-regression.json`, `m4-persistence-regression.json`, `m4-builder-regression.json`, `m4-detector.json`, `m4-payload.json`, desktop/light/dark/tablet/phone captures and `m4-mobile-canvas-focus.png`. The detector has advisory type/radius findings only; shared design metadata drift was not repaired. Review disposition is recorded in `M4_REVIEW.md` at its actual scope.

## Payload and limitations

The three engine artifacts total **5,785,085 bytes** (about 5.52 MiB), with a local gzip estimate of **1,936,145 bytes** (about 1.85 MiB). This excludes the surrounding PWA and is not measured production transfer. A new Chromium context reached local engine-ready in about one second on the already running development server; the exact run is in `m4-browser.json`. No production/Lighthouse/mobile-network speed claim is made. The engine still lazy-loads only on the experimental route.

Full native canvas screen-reader certification, physical touch/phone, Safari, real model quality/free-tier limits, actual deployed Edge bundle and hosted private PostgREST end-to-end tests remain unverified. Some native catalog items have no simulation model; desktop-only CLI, GitHub and hardware upload behavior is not equivalent in a browser. Retain the explicit simulation limits and native notices. No new app dependency, provider routing, proxy, hook, landing or extension change was introduced.

See `CAPABILITIES.md` for the capability/limitation matrix and `RELEASE.md` for the separately gated rollout/rollback procedure. M0–M4 local completion is not release approval or hardware verification.
