# M3: local structured circuit builder

Completed locally on `codex/playground-design-electronics`, after the owner's explicit M3 approval. No live AI request, hosted migration, push or deployment was performed. M2 checkpoint `318daf3e21b976c33b91ef4cdc53a6fe127a8ed9` remains the rollback point. The original Playground remains the default.

## Delivered workflow

Ask OHMI has a separate **Build a circuit with OHMI** disclosure. It preserves the ordinary chat draft and attachment workflow. A build is an explicit action, with one request UUID, pending/stop/status feedback, and account-bound recovery. Cancel means stop waiting; it does not promise server cancellation. An unresolved request blocks another generation until status is checked. Session storage holds only the pending UUID under an account-specific key, never a prompt, sketch, token or circuit.

The authenticated same-origin `/api/playground/build/` proxy forwards to the existing web Edge handler. The planner uses only Groq `openai/gpt-oss-120b`, strict JSON Schema, 3,072 maximum output tokens, a 20-second provider deadline and bounded response bodies. No streaming tools, repair loop, hidden retry or fallback is introduced. Existing chat/media provider routing is preserved. The new additive service-only admission wrapper reuses existing owner checks, request locking, replay, 60-second lease and completion/message persistence. It remains a local migration draft.

Three Edge gates must be true before inference: `OHMI_CIRCUIT_BUILD_ENABLED`, `OHMI_CIRCUIT_BUILD_FREE_TIER_VERIFIED`, and existing `GROQ_FREE_TIER_CONFIRMED`; existing Groq enable/key requirements also apply. Next requires its existing web AI flag and the new build flag. Both build flags default off when absent. **These names are configuration gates, not evidence of a free account.** Actual account tier, organization limits and permission for live qualification remain unverified and separately gated. Tests inject a synthetic key and a mocked transport; they never contact Groq.

The qualified automatic builder supports one Uno or battery, 1–8 LEDs with dedicated series resistors, and optional switch/breadboard. It validates exact fields, types, catalog pins, values, sizes, unique IDs, connection references, direct output/power shorts, resistor bypass/sharing, conservative 20 mA LED/output current and 0.25 W resistor bounds. Resistor-network traversal is bounded. Unsupported circuits must return an honest explanation with no partial circuit. The full **791-entry manual engine catalog remains available**; this milestone does not qualify every native component for AI generation. Arduino sketches are interpreted by the upstream subset, not compiled for a physical MCU.

An owner-bound saved build link opens the experimental workspace. Validated planner caveats are visible in results and included before opening direct handoffs. The existing native MCP tools construct a scratch document with connections in all three views. The actual simulator produces 80 samples over four seconds. Reported sketch errors, warnings or damage prevent opening. The previous active document remains unchanged until explicit atomic open; undo is retained and private save identity detaches to avoid overwriting a saved project. A collapsible, accessible table shows the captured LED brightness timeline and labels it as historical simulation evidence, not live verification after edits.

`.dez` preserves native editability. `.ino` downloads each Arduino board's exact complete sketch without rewriting it. Existing native menus, editor code, views and exporters remain available.

## Limits, rollout and rollback

Native accessibility and final mobile presentation remain M4.
